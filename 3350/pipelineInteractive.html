What Is a Machine Learning Pipeline?

Build the idea yourself: split data → learn preprocessing from training data → transform → train model → predict → evaluate.

Step 1 of 10

Why do we need a pipeline?

In Python, you have already written machine-learning code with several steps. Imagine predicting house prices using features such as income, house age, and population.

Raw X→StandardScaler→Regression Model→Prediction

Which two operations should always stay together?

Pipeline = one object that organizes a sequence of ML operations. Instead of remembering to run each operation separately, we define the workflow once.
Step 2 of 10

First: split BEFORE learning from the data

Suppose we have 12 observations. Click the button to create training and test sets.

Training set: used to learn preprocessing parameters and model parameters.
Test set: kept separate until evaluation. It represents unseen data.

Why do we keep test data separate?

Step 3 of 10

What does StandardScaler actually learn?

Suppose one training feature contains:

X_train = [10, 20, 30]

StandardScaler first fits on these training values. It learns their mean and standard deviation.

Training mean = 20
Training standard deviation ≈ 8.16

These are learned from X_train only.
Important vocabulary: fit() means learn something from data. For StandardScaler, it learns the mean and standard deviation.
Step 4 of 10

Then transform the data

After fitting, StandardScaler uses what it learned:

z = (x − training_mean) / training_standard_deviation

For x = 30:

(30 − 20) / 8.16 ≈ 1.225

The value 30 is now expressed relative to the training distribution.
transform() does not learn a new mean or standard deviation. It applies the values already learned during fit().
Step 5 of 10

The most important idea: avoid data leakage

Suppose the test set is [40, 50]. Which workflow is correct?

❌ Workflow A

Combine train + test → fit scaler → split → train model

✓ Workflow B

Split → fit scaler on train only → use that scaler to transform train AND test
Data leakage happens when information from data that should be unseen influences training. If the scaler learns from the test set, the test set has already influenced the workflow before evaluation.
Step 6 of 10

Now put scaler + model into one Pipeline

This is the pattern from your Python work:

ols = Pipeline([ ("scaler", StandardScaler()), ("linreg", LinearRegression()) ])
1. StandardScaler→2. LinearRegression
Nothing has run yet.
The names "scaler" and "linreg" let us access individual steps later using ols.named_steps[...].
Step 7 of 10

What happens when you call pipeline.fit()?

ols.fit(X_train, y_train)

Predict the hidden operations before revealing them.

X_train→Scaler.fit()→Scaler.transform()→Model.fit()
One call to pipeline.fit() coordinates all of this for you.
Step 8 of 10

What happens when you call pipeline.predict()?

y_pred_test = ols.predict(X_test)

Does the scaler learn a new mean from X_test?

X_test→Scaler.transform()→Trained Model.predict()→ŷ_test
This is why Pipeline is so useful: the exact same preprocessing logic is automatically applied at prediction time.

Evaluate the complete workflow

Your evaluation helper fits the model, predicts on train/test data, and calculates SSE, MSE, RMSE, and R².

MetricQuestion it answers
SSEWhat is the total squared prediction error?
MSEWhat is the average squared error?
RMSEWhat is the typical error size, in the target's units?

Remember: A pipeline is not a new machine-learning algorithm. It is a safe, organized way to connect the steps of your machine-learning workflow.
