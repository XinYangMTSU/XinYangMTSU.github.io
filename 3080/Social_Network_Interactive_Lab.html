The Adjacency List

unordered_map<string, vector<string>> friendList;

Key: string

User name, e.g. "Alice".

Value: vector<string>

List of adjacent users (friends).

Alice → [Bob, Charlie]

find(user)

Step 4 of 14

Pass-by-Constant-Reference

void addUser(const string& user); void addFriendship(const string& user1, const string& user2);

& reference

Avoids making another copy of the string.

const

Prevents modification through this parameter.

Step 5 of 14

addFriendship(): Bi-directional Edge

friendList[user1].push_back(user2); friendList[user2].push_back(user1);
Alice ↔ Bob
The friendship is stored in both adjacency lists, because the graph represents friendship as bi-directional.

Step 8 of 14

const at the End of the Function

void displayFriends(const string& user) const; void suggestFriends(const string& user) const;
The trailing const promises that the member function does not modify the object's member variables.

Step 10 of 14

Filter Invalid Suggestions

if (friendOfFriend != user && find(friendList.at(user).begin(), friendList.at(user).end(), friendOfFriend) == friendList.at(user).end())

Filter 1

Do not suggest the user themself.

Filter 2

Do not suggest an existing direct friend.

Step 11 of 14

Why set?

set<string> suggestions; suggestions.insert(friendOfFriend);
A candidate might be discovered through multiple mutual friends. A set keeps each suggestion unique.
same candidate found twice → stored once
