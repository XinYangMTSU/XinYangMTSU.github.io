Step 1 of 12

How can something be defined using itself?

A recursive definition may look circular because the item being defined appears in its own definition. It works because recursion has a place to start.

1. Basis / Base Case

Explicitly gives one or more simple starting cases.

2. Recursive Step

Defines new cases using cases we already know.
Known starting value→Rule→New value→Rule again...

Step 2 of 12

Recursively Defined Sequences

A sequence is an ordered list. We can write its terms as S(1), S(2), ..., S(n), ... or S₁, S₂, ..., Sₙ, ...

Recurrence relation: a formula that defines a sequence term using one or more earlier terms.

Example:

S(1) = 2
S(n) = 2S(n−1),   n ≥ 2

Which line is the base case?

Step 4 of 12

Recursive algorithm: calls itself

S(n) if n = 1 then return 2 else return 2 * S(n-1) end if

Choose n and watch the call stack grow.

The computer must keep track of unfinished function calls until it reaches S(1).
Step 5 of 12

Why can recursion use a lot of stack memory?

To compute S(5), calls are nested:

S(5) → S(4) → S(3) → S(2) → S(1)

Each unfinished call needs a stack frame. For this particular recurrence, the recursion depth grows with n.

Important distinction: recursion is often elegant and closely matches a recursive definition, but a direct recursive implementation is not automatically the most memory-efficient implementation.
Step 6 of 12

Iteration: carry the current value forward

i = 2 CurrentValue = 2 while i <= n do CurrentValue = 2 * CurrentValue i = i + 1 end while

Recursive idea

Ask another function call to compute the previous term.

Iterative idea

Keep the current value in a variable and update it inside a loop.
CurrentValue starts at 2.
For this sequence, iteration can compute the same result while keeping only a small amount of changing state rather than a deep chain of function calls.

Fibonacci needs TWO base cases

F(0)=0
F(1)=1
F(n)=F(n−2)+F(n−1),   n>1

Why are two starting values needed?

We begin with F(0)=0 and F(1)=1.
Step 8 of 12

Recursive Fibonacci creates repeated work

The simple recursive algorithm is:

F(n) if n <= 1 then return n else return F(n-2) + F(n-1)

For F(5), click to reveal the branching calls.

F(5) ├─ F(3) │ ├─ F(1) │ └─ F(2) │ ├─ F(0) │ └─ F(1) └─ F(4) ├─ F(2) ← repeated! │ ├─ F(0) │ └─ F(1) └─ F(3) ← repeated! ├─ F(1) └─ F(2)
Two different issues can make naive recursion expensive: deep call stacks use memory, and branching recursions such as naive Fibonacci also recompute the same values many times.
Step 9 of 12

Iterative Fibonacci remembers only what it needs next

F0 = 0 F1 = 1 while i <= n: Fn = F0 + F1 F0 = F1 F1 = Fn
State: F0=0, F1=1
Because the next Fibonacci value needs only the previous two values, the loop can update those two stored values repeatedly.

Practice: read a recurrence before coding it

Consider:

T(1)=1
T(n)=T(n−1)+3,   n>1

Predict T(4).

T(1)=1 T(2)=T(1)+3=4 T(3)=T(2)+3=7 T(4)=T(3)+3=10
Before writing C++ or pseudocode, identify: (1) base case, (2) recursive dependency, (3) what state an iterative version must carry.

Step 12 of 12

Mastery: Recursion or Iteration?

RecursionIteration
Often closely mirrors a recursive mathematical definitionUses loops and explicitly updated state
Natural for recursively structured problemsOften avoids deep call stacks
Function calls may add stack/overheadCan be preferable when stack usage/performance matters

Scenario: You must compute a simple recurrence for an extremely large n, and each term only needs the immediately previous value. Stack usage is a major concern. Which implementation is the more natural choice?

Big picture: A recursive definition tells us how objects depend on earlier objects. A recursive algorithm implements that dependency by calling itself. An iterative algorithm can often compute the same recurrence using a loop.
